# Runbook: Gigamon TA100 → свитч (работа на верстаке)

Пошаговый план для сессии с железом. Контекст и обоснование — в `gigamon.md`.

## Железо/факты, которые понадобятся

- CPU P2020E (PPC e500v2, BE), ASIC BCM56846 (Trident+).
- Serial: u-boot/bootmgr **115200**, ОС-консоль **9600** (`console=ttyS0,9600n8`).
- **`BOOTMGR_PASSWORD` пустой** — меню загрузчика не защищено.
- `admin` = uid 0, шелл = CLI. `root` = uid 0, но `/sbin/nologin`.
- passwd/shadow (изменяемые): `p8:/opt/tms/output/{passwd,shadow}`
  (в rootfs это симлинки `/etc/passwd → /var/opt/tms/output/passwd`).

---

## Шаг 0 — Бэкап (обязательно)

- Оригинальную SD НЕ трогать — это золотой бэкап.
- Все эксперименты — на **запасной** карте (залить туда `gigamon.bin`:
  `dd if=gigamon.bin of=/dev/sdX bs=4M status=progress`).

## Шаг 1 — Получить root через `init=/bin/bash`

1. Подключить serial (115200 8N1), включить питание.
2. Прервать отсчёт меню **bootmgr** (любая клавиша; пароля нет).
3. Отредактировать строку загрузки образа 1, дописать в конец:
   `init=/bin/bash rw`
4. Загрузиться → root-shell без пароля.
5. Если ФС смонтирована ro: `mount -o remount,rw /`

Сделать доступ постоянным (на выбор):
```sh
# вариант A: задать пароль admin (он уже uid 0, шелл CLI)
passwd admin

# вариант B: дать root нормальный шелл
vi /var/opt/tms/output/passwd     # root: .../sbin/nologin -> /bin/bash
passwd root
```
(правки на запасной карте можно сделать и офлайн, смонтировав p8.)

## Шаг 2 — Нормальная загрузка, проверка чипа

1. Перезагрузиться штатно (без init=), зайти под своей учёткой.
2. Проверить, что netdevd поднят и чип инициализирован:
```sh
ps  | grep -E 'netdevd|mgmtd|pm'
cat /proc/linux-kernel-bde          # чип виден на PCI?
lsmod | grep -E 'bde|knet'
ls -l /tmp/bcm.log                  # лог diag-шелла
```

## Шаг 3 — Найти вход для произвольной diag-команды

```sh
# перечислить узлы/параметры интерфейса netdevd
mdreq -v query iterate subtree /gv/internal/actions/netdevd

# заведомо рабочий вызов (как в их customer.sh) — убедиться, что механизм жив
mdreq action /gv/internal/actions/dump/netdevd mode string full
tail -n 40 /tmp/bcm.log             # что реально ушло в чип

# искать узел/параметр, принимающий строку-команду (mode/diag/command/cmd)
```
Цель: найти узел, через который в шелл уходит произвольная строка
(`vlan create ...`, `port ...`, `l2 add ...`).

Если сервисный путь не даётся — резерв: остановить pm/netdevd и запустить
netdevd интерактивно на tty, чтобы получить прямой `BCM.0>` (stdin-шелл).
Риск: standalone-netdevd может требовать окружение TMS для инициализации чипа —
проверять аккуратно.

## Шаг 4 — PoC L2 (доказать коммутацию в кремнии)

Через найденный вход выполнить в diag-шелле (примерная последовательность,
синтаксис уточнить по `help` в шелле):
```
vlan create 100
vlan add 100 pbmp=<порты>          # добавить порты в VLAN
port <порты> en=1                  # поднять порты
# включить learning/forwarding, снять TAP-ограничения если стоят
l2 show                            # смотреть, учатся ли MAC
```
Воткнуть два линка в порты одного VLAN, прогнать трафик, проверить `l2 show`
и счётчики портов — коммутируются ли пакеты и учатся ли MAC-адреса.

**Проверить особо:** MAC-learning. В aggregator/TAP-режиме learning часто
выключен на уровне конфигурации netdevd — возможно, придётся включать явно.
