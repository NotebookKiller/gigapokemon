# scripts/ — рабочие сниппеты для Gigamon TA100

Собрано из сессии 2026-09-30. Подробности — в `../session-2026-09-30.md`,
`../gigamon.md`, `../runbook.md`.

Помечено, **где** запускается каждый файл — контексты разные:

| Файл | Где | Что делает |
|------|-----|-----------|
| `uboot-root.txt` | u-boot `=>` (serial) | ручная загрузка в root-bash (`init=/bin/bash`) |
| `box-persistent-root.sh` | коробка, под `init=/bin/bash` | правит inittab → нормальная загрузка сразу даёт root-bash на консоли |
| `box-revert-inittab.sh` | коробка (root) | вернуть штатный логин CLI |
| `box-mount-partitions.sh` | коробка, под `init=/bin/bash` | смонтировать /var, /config, /proc (нет udev) |
| `box-chip-state.sh` | коробка (root, нормальная загрузка) | БЕЗОПАСНЫЙ дамп состояния чипа через netdevd |
| `host-write-card.sh` | хост (ПК) | записать `gigamon.bin` на SD + проверить |

## Порядок «с нуля до root»
1. На хосте: `host-write-card.sh` — записать образ на ~4 ГБ SDHC.
2. Вставить в железку, serial 115200. В меню bootmgr нажать любую клавишу → `c`.
3. В `=>` вставить команды из `uboot-root.txt` → попадаешь в root `#`.
4. На коробке выполнить содержимое `box-persistent-root.sh` (или скопировать файл).
5. Передёрнуть питание, в меню — Enter. Дальше нормальная загрузка сразу даёт
   root-bash на консоли (уже с поднятыми сервисами и чипом).

## Как файлы попадают на коробку
Простого сетевого доступа пока нет — либо копипастишь содержимое в консоль,
либо кладёшь на SD-раздел с ПК. Это **референс**, а не готовый деплой.

## НЕ использовать
`/var/bcm.sh` (gdb-раннер diag-команд) — дестабилизирует netdevd и вызывает
ребут. Оставлен только как артефакт исследования. Diag через gdb = тупик.
